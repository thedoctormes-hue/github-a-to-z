# Модуль 1. Веб-орбита: GitHub без консоли и установки программ

Многие думают, что для работы с GitHub нужно сразу открывать черный экран терминала и вводить сложные команды. Это заблуждение.

В этом модуле мы начнем с самого простого: зарегистрируемся, настроим твой профиль, усвоим три золотых правила безопасности, разберем ачивки и создадим первый репозиторий прямо в браузере.

---

## 1. Регистрация и выбор никнейма: твой бренд

Перейди на [github.com](https://github.com) и нажми **Sign up**.

При регистрации обрати внимание на три вещи:
1. **Username (Твой никнейм):**
   * Выбирай вдумчиво. Это не просто логин для сайта — это твой публичный адрес в резюме (например, `github.com/ivan-ivanov`).
   * Избегай случайных наборов цифр вроде `user1294829` или шутливых ников `nagibator2000`. Лучше всего: `имя-фамилия`, `фамилия-имя` или лаконичный профессиональный псевдоним.
2. **Email:** Указывай реальную почту, к которой у тебя есть постоянный доступ.
3. **Безопасность (2FA):** GitHub попросит включить двухфакторную аутентификацию (подтверждение через приложение вроде Google Authenticator или 2FAS). Это стандартное требование платформы для защиты аккаунта от взлома.

## 2. Три золотых правила старта любого проекта 🛡️

Прежде чем нажать кнопку «Создать репозиторий», запомни три правила гигиены, которые спасут твои нервы и безопасность:

### 1. Закон бункера (Private First)
> **Любой новый проект всегда создается закрытым (Private).**  
> Единственное исключение — специальный репозиторий-визитка твоего профиля.

* **Почему это критично:** По интернету круглосуточно рыщут сотни ботов-сканеров. Если в публичный проект случайно попадет пароль, токен или секретный ключ от базы — боты украдут его за 3–5 секунд.
* **Правило жизни:** Проект зреет в тени. Ты открываешь его миру (переключаешь в **Public**) только тогда, когда готов первый рабочий **MVP** (минимальный рабочий продукт), написана документация и проверено, что в коде нет забытых паролей.

### 2. Сначала чертеж, потом стройка (README-First)
> **Решил начать проект? Начни не с написания кода, а с оформления репозитория и README.**

* Если сразу броситься писать код, через 3 дня проект умрет: ты забудешь, что хотел сделать, запутаешься в мыслях и бросишь начатое.
* Сначала создай закрытый репозиторий и напиши в `README.md`:
  * Какую проблему решает этот проект?
  * Что в нем должно работать в первой версии?
  * Чек-лист из 3–5 задач.
  Код — это просто строительный материал. `README.md` — это твой архитектурный план.

### 3. Цифровой нотариус (Proof of Authorship) ⚖️
> **Твой GitHub — это юридическое и фактическое доказательство первенства твоих идей.**

* Каждый коммит в Git запечатан криптографическим хэшем (SHA) и неизменяемой датой с точностью до секунды.
* Если кто-то через полгода заявит: *«Я первый придумал этот сервис!»*, ты открываешь историю коммитов своего репозитория и показываешь: *«Вот мой коммит и черновик архитектуры от 12 октября. А где был ты?»*. Подделать эту историю задним числом невозможно.

## 3. Секретный репозиторий: визитка твоего профиля

Когда кто-то заходит на страницу твоего профиля, по умолчанию он видит пустую страницу и серые квадратики активности. Но у GitHub есть удобная возможность — **профильный README**.

Это блок текста на главной странице твоего профиля, где ты можешь рассказать о себе, своих учебных целях и технологиях, которые изучаешь.

### Как его включить:
1. В правом верхнем углу нажми на плюсик `+` ➔ **New repository**.
2. В поле **Repository name** введи **в точности свой никнейм** на GitHub.  
   *(Если твой логин `alex-dev`, имя репозитория должно быть строго `alex-dev`)*.
3. Появится специальная подсказка с котиком: *«You found a secret! ...»*.
4. Для визитки выбери статус **Public** (Публичный) и поставь галочку **Add a README file**.
5. Нажми зеленую кнопку **Create repository**.

Теперь текст из файла `README.md` этого репозитория отображается прямо на главной странице твоего профиля!

## 4. Ачивки профиля (GitHub Achievements) и цифровая репутация 🏆

В правой колонке твоего профиля есть специальный блок — **Achievements** (Ачивки). 
GitHub добавил систему наград, чтобы поощрять здоровую инженерную культуру и превратить учебу в увлекательную прокачку персонажа.

### Популярные ачивки и как их получить честным путем:
* 🦈 **Pull Shark:** вручается за слияние твоего первого Pull Request. Чем больше принятых PR, тем выше уровень бейджа (бронзовый x2, серебряный x3, золотой x4).
* ⚡ **Quickdraw:** вручается, если ты закрыл Issue или Pull Request менее чем за 5 минут после его открытия (знак моментальной реакции).
* 🧠 **Galaxy Brain:** вручается за 2 и более ответов во вкладке **Discussions**, которые автор вопроса отметил галочкой как принятое решение (**Accepted Answer**).
* 👯 **Pair Extraordinaire:** вручается за совместный коммит в паре. Чтобы получить ее, в сообщении коммита указывают соавтора:
  ```bash
  git commit -m "feat: добавил валидацию формы

  Co-authored-by: Name <partner@example.com>"
  ```
* 🤠 **YOLO:** вручается за слияние Pull Request без предварительного код-ревью (шуточная «пиратская» награда).
* 🧊 **Arctic Code Vault Contributor / Mars 2020 Helicopter:** легендарные архивные знаки тех, чей код был навечно запечатан во всемирном архиве подо льдами Шпицбергена или участвовал в миссии вертолета Ingenuity на Марсе.

### Как настроить показ наград:
Если ты хочешь скрыть ачивки или наоборот закрепить лучшие из них на витрине:  
`Клик на аватарку` ➔ `Settings` ➔ `Public profile` ➔ прокрути вниз до `Achievements` ➔ отметь или сними галочку *Show Achievements on my profile*.

> ⚠️ **Предостережение разведки (Анти-спам):**  
> В интернете часто встречаются сервисы, предлагающие «накрутить все ачивки за 10 минут». Никогда не делай этого. Спам пустыми фейковыми PR мгновенно детектируется антифрод-системами GitHub, приводит к позорному бану аккаунта и вызывает презрение у тимлидов. Настоящая ачивка ценна только тогда, когда заработана реальным кодом.

## 5. Волшебная клавиша `.` (Web-редактор прямо в браузере)

Как отредактировать этот файл? На GitHub есть способ запустить редактор в один клик:

1. Открой созданный репозиторий в браузере.
2. Нажми на клавиатуре английскую клавишу **точки** (`.`).
3. Через пару секунд прямо в твоем браузере запустится полноценный редактор кода **VS Code for Web**!
4. В левой колонке ты увидишь список файлов. Нажми на `README.md`.
5. Теперь ты можешь писать и форматировать текст с подсветкой и удобным просмотром.

### Как сохранить изменения (сделать коммит):
1. Отредактируй текст в файле.
2. Нажми на третью иконку слева в боковой панели (иконка ветвления с синим кружком — **Source Control**).
3. В поле сообщения сверху напиши, что ты изменил (например: `feat: обновил информацию о себе`).
4. Нажми синюю кнопку **Commit & Push** (или синюю галочку).
5. Изменения сохранены на сервере GitHub.

## 6. Экспресс-курс по Markdown за 5 минут

Файлы с расширением `.md` написаны на языке разметки **Markdown**. Это простой способ оформлять текст знаками препинания без мышки и сложных меню.

Вот основные правила, которых хватит для 95% задач:

### Заголовки
Символ решетки `#` задает заголовок. Чем больше решеток, тем меньше размер:
```markdown
# Самый крупный заголовок (H1)
## Заголовок раздела (H2)
### Подзаголовок (H3)
```

### Выделение текста
```markdown
**Жирный текст** для важных мыслей
*Курсив* для примечаний
~~Зачеркнутый текст~~
```

### Списки и задачи (чек-боксы)
```markdown
* Пункт списка
* Еще один пункт

1. Шаг первый
2. Шаг второй

- [ ] Невыполненная задача
- [x] Выполненная задача
```

### Ссылки и картинки
```markdown
[Текст ссылки](https://github.com)
![Подпись к картинке](https://via.placeholder.com/150)
```

### Блоки кода
Чтобы код отображался аккуратным шрифтом программистов:
````markdown
Короткий код внутри строки: `print("Hello")`

Большой блок кода с подсветкой:
```python
def greet(name):
    return f"Привет, {name}!"
```
````

## 7. Лабораторная работа №1: Оформи свой профиль

### Задание:
1. Зарегистрируйся на GitHub (если у тебя еще нет аккаунта).
2. Создай секретный репозиторий `твой-логин/твой-логин`.
3. Открой его и нажми клавишу `.` для запуска онлайн-редактора.
4. Оформи `README.md` своего профиля по структуре:
   * **Приветствие:** как тебя зовут и в какой сфере ты развиваешься.
   * **О себе:** 2-3 предложения о том, какие технологии сейчас изучаешь (например: Python, HTML/CSS, основы алгоритмов).
   * **План на ближайший месяц:** чек-лист из 3 конкретных задач (например: `- [ ] Освоить базовые команды Git`, `- [ ] Написать первую программу`).
   * **Контакты:** ссылка на твой Telegram или соцсеть для связи.
5. Напиши сообщение коммита и нажми **Commit & Push**.
6. Перейди на главную страницу своего профиля `github.com/твой-логин` и проверь результат.
