# 🧭 Модуль 0: Разведка на местности (Git vs GitHub)

> *«Прежде чем строить замки в облаках, убедись, что твердо стоишь на земле.»*

Добро пожаловать на исходный рубеж! Если вы никогда раньше не сталкивались с контролем версий, не пугайтесь незнакомых слов. В этом модуле мы снимем туман войны и разложим базовые понятия по полочкам.

---

## 1. Главная путаница новичков: Git — это НЕ GitHub 🧩

Очень часто эти два слова используют как синонимы. Но между ними такая же разница, как между:
* 🚗 **Двигателем** (Git) и **Автосервисом с гоночной трассой** (GitHub).
* 📷 **Фотоаппаратом** (Git) и **Instagram** (GitHub).
* 📝 **Текстовым редактором** (Git) и **Издательством** (GitHub).

### Что такое Git?
**Git** — это локальная консольная программа (инструмент контроля версий), созданная Линусом Торвальдсом в 2005 году.
* Она работает прямо на вашем компьютере.
* Ей не нужен интернет.
* Она умеет делать «снимки» (коммиты) состояния ваших файлов, чтобы в любой момент можно было вернуться назад во времени, если что-то сломалось.

### Что такое GitHub?
**GitHub** — это гигантская облачная платформа (веб-сервис), которая:
* Хранит ваши Git-репозитории в облаке.
* Позволяет разработчикам со всего мира работать над одним проектом вместе.
* Предоставляет интерфейс для просмотра кода, обсуждения задач (Issues), проверки чужого кода (Pull Requests) и автоматизации тестирования (GitHub Actions).

> 💡 **Резюме:** Git делает снимки изменений у вас на диске. GitHub позволяет делиться этими снимками с миром и строить вокруг них совместную работу.

## 2. Зачем разработчикам контроль версий? 🕰️

Вспомните, как обычные люди сохраняют важные документы:
```text
Диплом_финал.docx
Диплом_финал_правки_мамы.docx
Диплом_финал_правки_научника_РЕАЛЬНЫЙ.docx
Диплом_финал_ТОЧНО_ЭТОТ_v2_FINAL.docx
```

Знакомо? В программировании это приводит к катастрофе. Если в проекте 10 000 файлов, такой подход убьет проект за пару дней.

### Что дает Git:
1. **Машина времени:** Вы можете откатить любую строчку кода до состояния часовой давности, прошлой недели или трехлетней давности.
2. **Параллельные вселенные (Ветки):** Вы можете экспериментировать с новой фичей в отдельной ветке. Если идея провалилась — ветка удаляется одним кликом, а основной рабочий проект остается нетронутым.
3. **Ответственность:** Всегда видно, *кто*, *когда* и *зачем* изменил конкретную строчку кода (команда `git blame`).

## 3. Анатомия репозитория на GitHub 🏛️

Когда вы открываете любой проект на GitHub, перед вами предстает командный пункт:

| Вкладка / Элемент | Для чего служит |
| :--- | :--- |
| **Code** | Файловое дерево проекта, история коммитов, просмотр файлов и веток. |
| **Issues** | Доска задач и баг-трекер: здесь сообщают об ошибках и предлагают улучшения. |
| **Pull Requests (PR)** | Предложения изменений: место, где код рецензируют перед объединением. |
| **Actions** | Встроенные роботы: автоматический запуск тестов, линтеров и деплой. |
| **Projects** | Канбан-доски для управления проектом (аналог Trello). |
| **Security** | Настройки безопасности, поиск уязвимостей в зависимостях и сканирование утечек. |
| **Insights** | Аналитика: графики активности, вклад участников, статистика коммитов. |

## 4. Базовый словарь шпиона (Глоссарий) 📖

Запомните эти 7 терминов, они будут сопровождать вас на каждом шагу:

1. **Репозиторий (Repo):** Папка вашего проекта, историю которой отслеживает Git.
2. **Коммит (Commit):** Фиксация («снимок») изменений. Имеет автора, дату и поясняющее сообщение.
3. **Ветка (Branch):** Независимая линия разработки. Главная ветка обычно называется `main`.
4. **Клон (Clone):** Полная копия удаленного репозитория с GitHub на ваш локальный диск.
5. **Форк (Fork):** Копия чужого репозитория в ваш личный профиль на GitHub.
6. **Push (Отправить):** Отправка ваших локальных коммитов в облако на GitHub.
7. **Pull (Забрать):** Скачивание свежих изменений из облака на ваш компьютер.
