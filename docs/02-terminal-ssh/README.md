# Модуль 2. Мост к терминалу: установка Git, безопасная авторизация и первый Push

В первом модуле мы работали прямо в браузере. Это удобно для быстрых правок, но настоящие программы пишутся на вашем компьютере — в локальном редакторе кода.

В этом модуле мы сделаем главный шаг: установим Git на компьютер, свяжем его с GitHub безопасным ключом и отправим первый проект в облако из командной строки.

Не бойтесь черного экрана: мы пройдем каждый шаг за руку с пояснениями.

---

## 1. Установка Git на компьютер

Первым делом проверим: вдруг Git у вас уже установлен?  
Откройте терминал (в Windows — командную строку или PowerShell, на Mac/Linux — программу «Терминал») и введите:

```bash
git --version
```

Если вы увидели номер версии (например, `git version 2.43.0`), Git уже готов к работе. Если команда не найдена — установим его:

* **Windows:**
  1. Скачайте установщик с официального сайта [git-scm.com](https://git-scm.com/download/win).
  2. Запустите установщик. При установке можно нажимать «Next» со всеми настройками по умолчанию.
  3. Вместе с Git установится удобный терминал **Git Bash** — для работы на Windows мы рекомендуем использовать именно его.
* **macOS:**
  * Достаточно ввести в терминале `git --version`. Если Git не установлен, система сама предложит установить Command Line Developer Tools — нажмите «Установить».
  * Или через менеджер пакетов Homebrew: `brew install git`.
* **Linux (Ubuntu/Debian):**
  ```bash
  sudo apt update && sudo apt install git -y
  ```

---

## 2. Представьтесь системе (Identity)

После установки Git нужно один раз сообщить, кто автор будущих коммитов. Эти данные будут записываться в каждый ваш снимок проекта.

Выполните две команды в терминале (замените данные на свои):

```bash
git config --global user.name "Иван Иванов"
git config --global user.email "ivan@example.com"
```

> ⚠️ **Важное правило:** Указывайте **тот же самый email**, на который зарегистрирован ваш аккаунт GitHub! Если почта не совпадет, GitHub не поймет, что автор коммитов — именно вы, и не будет окрашивать зеленые квадратики активности в вашем профиле.

Проверить, что настройки сохранились:
```bash
git config --list
```

## 3. Связываем компьютер и GitHub (Авторизация без слез)

Раньше для отправки кода на GitHub можно было просто ввести логин и пароль в терминале. С 2021 года GitHub **полностью запретил** обычные пароли из соображений безопасности.

У вас есть два пути связать свой компьютер с GitHub:

### Вариант А: Современный экспресс-вход через GitHub CLI (Рекомендуется)
Если не хочется вручную возиться с генерацией криптографических ключей, установите официальную утилиту GitHub:
* Windows: `winget install --id GitHub.cli`
* macOS: `brew install gh`
* Linux: `sudo apt install gh`

Затем введите в терминале:
```bash
gh auth login
```
1. Выберите **GitHub.com** ➔ нажмите Enter.
2. Выберите протокол **SSH** ➔ нажмите Enter.
3. На вопрос о генерации SSH-ключа выберите **Yes**.
4. Выберите **Login with a web browser**.
5. Терминал покажет 8-значный код (например, `ABCD-1234`) и откроет страницу авторизации в браузере. Введите код, подтвердите вход — и всё! Ваш компьютер авторизован навсегда.

---

### Вариант Б: Классический инженерный путь через SSH-ключ
SSH-ключ — это пара из двух файлов:
* **Приватный ключ** (лежит только на вашем компьютере, никому его не показывайте).
* **Публичный ключ** (загружается на GitHub). Это как замок, который открывается только вашим приватным ключом.

#### Шаг 1. Генерация ключа:
Введите команду в терминале (вместо почты укажите свой email на GitHub):
```bash
ssh-keygen -t ed25519 -C "ivan@example.com"
```
На все вопросы (куда сохранить, ввести ли пароль) просто нажимайте **Enter** до тех пор, пока не появится рисунок случайного кода (randomart).

#### Шаг 2. Копирование публичного ключа:
Выведите содержимое публичного ключа на экран:
* Windows (Git Bash): `cat ~/.ssh/id_ed25519.pub`
* macOS: `pbcopy < ~/.ssh/id_ed25519.pub` (скопирует сразу в буфер обмена)
* Linux: `cat ~/.ssh/id_ed25519.pub`

Скопируйте строку целиком — она начинается со слов `ssh-ed25519 ...` и заканчивается вашим email.

#### Шаг 3. Добавление на GitHub:
1. Зайдите на GitHub ➔ нажмите на свой аватар в правом верхнем углу ➔ **Settings**.
2. В левой колонке выберите **SSH and GPG keys**.
3. Нажмите зеленую кнопку **New SSH key**.
4. В поле **Title** напишите название своего компьютера (например, `My Laptop`).
5. В поле **Key** вставьте скопированную строку.
6. Нажмите **Add SSH key**.

#### Шаг 4. Проверка связи:
Введите в терминале:
```bash
ssh -T git@github.com
```
На вопрос `Are you sure you want to continue connecting (yes/no)?` напечатайте **yes** и нажмите Enter.  
Если вы увидели:  
`Hi username! You've successfully authenticated...` — мост между вашим компьютером и облаком работает идеально!

## 4. Золотой цикл Git: от пустой папки до облака

Теперь создадим наш первый локальный проект и отправим его на GitHub.

### Шаг 1: Создаем папку проекта
В терминале перейдите в удобное место и создайте папку:
```bash
mkdir my-first-project
cd my-first-project
```

### Шаг 2: Включаем наблюдение Git (`git init`)
```bash
git init
```
Эта команда создает скрытую папку `.git`. Теперь эта папка стала Git-репозиторием.

### Шаг 3: Создаем файл
Создайте файл `README.md` (в блокноте или через терминал):
```bash
echo "# Мой первый проект через консоль" > README.md
```

### Шаг 4: Проверяем статус (`git status`)
Это ваша главная команда-компас. Она показывает текущее состояние репозитория:
```bash
git status
```
Git покажет красный файл `README.md` в блоке *Untracked files* (неотслеживаемые файлы).

### Шаг 5: Добавляем файл в подготовку (`git add`)
Представьте, что вы собираете посылку. Команда `git add` кладет файл в коробку:
```bash
git add README.md
```
*(Если нужно добавить сразу все измененные файлы, пишут `git add .`)*.  
Снова введите `git status` — файл стал зеленым. Он готов к упаковке.

### Шаг 6: Делаем снимок (`git commit`)
Запечатываем коробку и пишем на ней бирку с описанием:
```bash
git commit -m "feat: мой первый коммит из консоли"
```
Поздравляем: снимок сохранен локально на вашем диске!

### Шаг 7: Создаем удаленный репозиторий на GitHub
1. Перейдите на [github.com](https://github.com) ➔ нажмите `+` ➔ **New repository**.
2. Назовите его `my-first-project`.
3. Оставьте его **Public**, но **НЕ ставьте галочку «Add a README file»** (файл мы уже создали на компьютере).
4. Нажмите **Create repository**.
5. Скопируйте ссылку на репозиторий по протоколу SSH (вид: `git@github.com:ваш-логин/my-first-project.git`).

### Шаг 8: Связываем и отправляем в облако (`git remote` и `git push`)
Вернитесь в терминал и выполните две финальные команды:

```bash
# 1. Привязываем адрес репозитория на GitHub (даем ему имя origin)
git remote add origin git@github.com:ваш-логин/my-first-project.git

# 2. Переименовываем ветку в main (стандарт)
git branch -M main

# 3. Отправляем изменения в облако!
git push -u origin main
```

Обновите страницу репозитория на GitHub в браузере — ваш файл и коммит появились там! 🚀

## 5. Как забрать изменения из облака (`git pull`)

Если кто-то (или вы сами через сайт) отредактировал файл на GitHub, чтобы скачать свежие изменения на компьютер, достаточно выполнить одну команду:

```bash
git pull
```

Git сравнит версии и аккуратно обновит файлы на вашем диске.

## 6. Частые ошибки новичков и их решение 🚑

| Симптом / Ошибка | В чем причина | Что делать |
| :--- | :--- | :--- |
| `Permission denied (publickey)` | GitHub не знает ваш SSH-ключ | Проверьте шаг 3: скопирован ли ключ `id_ed25519.pub` в Settings ➔ SSH keys. |
| `fatal: not a git repository` | Вы находитесь в обычной папке | Вы забыли ввести `git init` или находитесь не в той директории (проверьте через `pwd`). |
| `fatal: remote origin already exists` | Связь с удаленным репо уже была добавлена | Проверьте адрес командой `git remote -v`. Если он неверный, удалите: `git remote remove origin`. |
| Квадратики на GitHub не зеленеют | Email в `git config` отличается от GitHub | Выполните `git config --global user.email "ваш-реальный-email-на-github"`. |
