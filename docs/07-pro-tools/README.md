Поздравляем! Вы прошли путь от абсолютного нуля до настройки CI/CD и хостинга. 

Теперь вы умеете всё, что нужно для повседневной работы. Но чтобы стать по-настоящему быстрым и эффективным специалистом, вам нужен арсенал профессионала:
1. **GitHub CLI (`gh`):** управление проектом прямо из терминала без открытия браузера.
2. **Model Context Protocol (MCP):** как безопасно подключить ИИ-ассистентов к своему репозиторию, какие инструменты разрешить, а какие — смертельно опасно оставлять включенными.

## 1. Консольный штурвал: GitHub CLI (`gh`) ⚡

Обычный `git` умеет работать только с файлами на диске. Чтобы создать Pull Request или прочитать Issue, разработчикам раньше приходилось постоянно переключаться в браузер.

Утилита **GitHub CLI (`gh`)** переносит всю мощь сайта прямо в ваш терминал.

### Топ-5 команд, которые экономят часы жизни:

1. **Клонирование репозитория в один клик:**
   ```bash
   gh repo clone username/project-name
   ```
   *(Больше не нужно копировать длинные URL-адреса из адресной строки)*.

2. **Создание Pull Request за 3 секунды:**
   ```bash
   gh pr create --title "feat: новая функция" --body "Closes #15"
   ```
   *(Терминал сам создаст PR и выведет ссылку на него)*.

3. **Просмотр чужого PR локально:**
   ```bash
   gh pr checkout 12
   ```
   *(GitHub CLI сам скачает ветку из PR #12 коллеги и переключит вас на нее для проверки)*.

4. **Работа с задачами (Issues):**
   ```bash
   gh issue list           # Посмотреть список открытых задач
   gh issue create         # Интерактивно создать новую задачу
   ```

5. **Открыть текущий проект в браузере:**
   ```bash
   gh browse
   ```
   *(Мгновенно открывает страницу репозитория в браузере по умолчанию)*.

## 2. Model Context Protocol (MCP) и ИИ-агенты 🤖

В 2026 году разработка немыслима без ИИ-ассистентов (Cursor, Claude Code, Antigravity, Cline). Но копировать код руками из чата — прошлый век.

> **MCP (Model Context Protocol)** — это открытый стандарт, который позволяет ИИ подключаться напрямую к GitHub через набор специализированных инструментов (Tools).

Однако подключить GitHub MCP сервер «как есть» со всеми правами — это колоссальный риск. По умолчанию сервер дает агенту более 30 инструментов, часть из которых может уничтожить проект за секунду.

Ниже представлена **Матрица безопасности MCP**, основанная на принципе наименьших привилегий (Principle of Least Privilege):

---

### 🟢 ЗЕЛЕНАЯ ЗОНА: Инструменты MUST HAVE (Разрешить агенту)

Эти инструменты превращают ИИ в аккуратного исследователя и стажера:

| Инструмент MCP | Что делает | Почему безопасен |
| :--- | :--- | :--- |
| `get_file_contents` / `read_file` | Читает файлы проекта | Чтение безопасно. Агент изучает архитектуру. |
| `search_code` / `search_repositories` | Ищет функции по проекту | Позволяет находить контекст без ручной подсказки человека. |
| `create_branch` | Создает новую ветку | Изолирует работу агента в безопасном «карантине». |
| `create_or_update_file` | Создает/правит файлы | **Разрешено строго в фиче-ветках** (запрещено в `main`). |
| `create_pull_request` | Открывает PR | Предлагает результат работы на ревью человеку (HITL). |
| `list_issues` / `get_issue` | Читает задачи | Позволяет агенту понимать техническое задание. |
| `add_issue_comment` | Оставляет комментарий | Агент отчитывается о статусе выполнения. |

---

### 🔴 КРАСНАЯ ЗОНА: Инструменты MUST DISABLE (Немедленно отключить!)

Эти инструменты представляют смертельную угрозу и должны быть **заблокированы в конфигурации MCP**:

| Опасный инструмент | В чем смертельная опасность |
| :--- | :--- |
| ❌ **`merge_pull_request`** | **Ломает принцип HITL!** Если агент может сам слить свой PR, он зальет непроверенные галлюцинации прямо в священный `main`. Право на слияние принадлежит **только человеку**. |
| ❌ **`delete_branch` / `delete_file` / `delete_repo`** | **Риск безвозвратной потери данных.** Из-за бага в промпте агент может стереть чужую ветку или снести репозиторий. |
| ❌ **Прямой push в `main` / `master`** | Прямая запись в защищенные ветки в обход Pull Request уничтожает стабильность кодовой базы. |
| ❌ **`manage_secrets` / `get_secret`** | Агент **никогда** не должен иметь доступа к боевым токенам и переменным CI/CD (GitHub Secrets). |
| ❌ **`manage_collaborators` / `admin_*`** | Управление правами доступа пользователей — исключительная монополия владельца проекта. |

## 3. Черная магия Git: Спасение утопающих (`git reflog`) 🧙‍♂️

Рано или поздно наступает день, когда по ошибке вводится страшная команда:
```bash
# Случайно удалена важная ветка с недельной работой:
git branch -D my-feature-branch

# Или случайно сброшены коммиты:
git reset --hard HEAD~5
```

Кода больше нет в `git log`. Файлы пропали. В глазах темнеет.

### Спокойно: Git никогда ничего не удаляет сразу!
В Git встроена бортовая черная шкатулка — **`git reflog`** (Reference Log). Она записывает каждое перемещение указателя `HEAD`, каждый коммит, переход и сброс, которые вы совершали на компьютере за последние 30–90 дней.

### Алгоритм воскрешения за 2 шага:

#### Шаг 1: Открываем черный ящик
```bash
git reflog
```
Вы увидите хронологический список ваших действий:
```text
a1b2c3d HEAD@{0}: reset: moving to HEAD~5 (катастрофа!)
f4e5d6c HEAD@{1}: commit: feat: реализована сложная логика (ВОТ ОН!)
9876543 HEAD@{2}: checkout: moving from main to my-feature-branch
```

Найдите строку, где ваш код был жив, и скопируйте ее хэш (в примере выше: `f4e5d6c`).

#### Шаг 2: Воскрешаем ветку из мертвых
Создайте новую ветку прямо из скопированного хэша:
```bash
git switch -c recovered-branch f4e5d6c
```

**Магия свершилась:** вся ваша удаленная работа, все файлы и коммиты вернулись на экран в первозданном виде! Вы спасены.
