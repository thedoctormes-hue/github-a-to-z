# 🧪 Лабораторная работа №4: Настройка цифрового щита (OPSEC & Gitignore)

> **Цель работы:** Научиться защищать репозиторий от утечек секретов: создать правильный `.gitignore`, настроить связку `.env` и `.env.example`, проверить статус игнорирования и включить защиту от случайного пуша ключей.

---

## 📋 Пошаговый сценарий

### Шаг 1. Подготовка тестового проекта
Перейди в свой учебный репозиторий на компьютере:
```bash
cd test-git-lab
git switch main
git pull
```

---

### Шаг 2. Создание файлов конфигурации
Создай два файла в корне проекта:

1. **Реальный файл с секретом (локальный):**
   ```bash
   echo 'API_TOKEN="sk-proj-test12345fakekey"' > .env
   ```

2. **Публичный шаблон без секретов:**
   ```bash
   echo 'API_TOKEN="вставьте_ваш_секретный_ключ"' > .env.example
   ```

3. Выполни `git status`.  
   Ты увидишь, что Git видит **оба** файла: и `.env`, и `.env.example`.  
   *Если сейчас сделать коммит — секрет попадет в репозиторий!*

---

### Шаг 3. Установка щита (`.gitignore`)
Создай в корне репозитория файл `.gitignore` со следующим содержанием:

```gitignore
# Секреты и ключи
.env
*.key
*.pem

# Временные файлы и окружение
venv/
__pycache__/
.DS_Store
Thumbs.db
```

Сохрани файл.

---

### Шаг 4. Проверка работы щита
Снова введи команду-компас:
```bash
git status
```

**Обрати внимание на магию:**  
Файл `.env` **полностью исчез** из списка! Git больше не замечает его существования.  
В списке остались только:
* `.gitignore`
* `.env.example`

Добавь их в коммит и отправь на GitHub:
```bash
git add .gitignore .env.example
git commit -m "security: настроен .gitignore и шаблон .env.example"
git push origin main
```

Зайди на страницу репозитория на GitHub в браузере: файл `.env.example` на месте, а секретного `.env` там нет и никогда не будет.

---

### Шаг 5. Что делать, если файл УЖЕ отслеживался Git? (Важный трюк)
Часто бывает, что новичок сначала закоммитил файл, а уже потом вписал его в `.gitignore`.  
В этом случае `.gitignore` не сработает автоматически, потому что Git уже следит за файлом.

Чтобы заставить Git «забыть» файл без его физического удаления с диска, используется команда:
```bash
git rm --cached имя-файла
```

Попробуй проверить эту команду:
1. Создай файл `temp.log`: `echo "тестовый лог" > temp.log`
2. Закоммить его: `git add temp.log && git commit -m "temp"`
3. Допиши `*.log` в `.gitignore`.
4. Введи `git rm --cached temp.log`.
5. Сделай коммит: `git commit -m "fix: файл лога исключен из отслеживания"`.  
*Файл останется у тебя на диске, но Git перестанет его отслеживать.*

---

### Шаг 6. Включение GitHub Push Protection
1. Открой свой репозиторий на сайте [github.com](https://github.com).
2. Перейди во вкладку **Settings** ➔ раздел **Code security and analysis** (в левой колонке).
3. Найди блок **Secret scanning** и включи **Push protection** (переключатель в положение Enable).

> [!IMPORTANT]
> **⚠️ Тарифный радар (Push Protection на тарифе Free):**  
> Функция Push Protection бесплатна **только для публичных репозиториев**. В приватных репозиториях GitHub требует платную подписку GHAS. Если вы работаете в приватном репозитории и переключатель заблокирован — это нормальное поведение платформы: переключите репозиторий в Public для прохождения шага или убедитесь, что локальный `.gitignore` надежно скрывает файл `.env`.

4. Теперь репозиторий защищен не только локальным `.gitignore`, но и облачным радаром GitHub!

---

## ✅ Критерии успешного выполнения
1. В корне репозитория есть корректный файл `.gitignore`.
2. В репозиторий закоммичен шаблон `.env.example` без секретов.
3. Локальный файл `.env` существует на диске, но не отслеживается Git.
4. В настройках репозитория на GitHub включена функция **Push protection**.
