# Лабораторная работа №9: Наведение архитектурного порядка, ADR и практика git stash

## 🎯 Цель работы
1. Освоить безопасную синхронизацию и работу с тайником `git stash`.
2. Очистить локальный репозиторий от мертвых веток через `git fetch --prune`.
3. Создать правильную структуру каталогов по принципам Root Hygiene.
4. Написать свое первое официальное архитектурное решение (ADR).

---

## 🛠️ Шаг 1. Практика тайника: спасение незавершенной работы (`git stash`)

1. Открой терминал в своем учебном проекте `test-git-lab` (или создай новую тестовую папку).
2. Создай новую ветку:
   ```bash
   git switch -c feat/user-dashboard
   ```
3. Создай черновой файл `draft_logic.py` и напиши в нем любой незаконченный набросок:
   ```python
   # Черновик: расчет статистики
   def calculate_stats():
       pass
   ```
4. Добавь файл в отслеживание:
   ```bash
   git add draft_logic.py
   ```
5. Представь: тебе срочно нужно переключиться на `main`, но коммит делать нельзя!  
   Спрячь набросок в тайник:
   ```bash
   git stash
   ```
6. Проверь состояние рабочей папки:
   ```bash
   git status
   ```
   *Результат:* Папка идеально чистая! Файл `draft_logic.py` исчез из видимости.
7. Спокойно переключись на `main` и вернись обратно:
   ```bash
   git switch main
   git switch feat/user-dashboard
   ```
8. Достань свои наброски обратно:
   ```bash
   git stash pop
   ```
   *Результат:* Файл `draft_logic.py` со всеми изменениями моментально вернулся на свое место!

---

## 🛠️ Шаг 2. Санация мертвых веток

Выполни команду санитарной очистки удаленных ссылок:
```bash
git fetch --prune
```
Git проверит состояние сервера и удалит все локальные упоминания веток, которые уже были удалены на GitHub.

---

## 🛠️ Шаг 3. Наведение Root Hygiene

Приведи структуру своего проекта к образцовому виду:
1. Создай каталог для исходного кода:
   ```bash
   mkdir -p src tests docs/adr
   ```
2. Перемести рабочие скрипты внутрь `src/`:
   ```bash
   mv draft_logic.py src/
   ```
3. Убедись, что в корне репозитория остались только `README.md`, `.gitignore`, `LICENSE` и конфигурационные файлы.

---

## 🛠️ Шаг 4. Написание первого ADR (Architecture Decision Record)

1. В каталоге `docs/adr/` создай файл `0001-init-structure.md`:
   ```markdown
   # ADR-0001: Выбор модульной структуры проекта и стандартов каталогизации

   ## Статус
   Принято (Accepted) / Дата: 2026-10-12

   ## Контекст
   На раннем этапе проект содержал скрипты прямо в корне репозитория. 
   С ростом функционала это затрудняет тестирование и нарушает чистоту рабочей области.

   ## Решение
   1. Внедрить правило Root Hygiene: весь исходный код перенесен в каталог `src/`.
   2. Все автоматические тесты размещаются в каталоге `tests/`.
   3. Все архитектурные решения фиксируются в `docs/adr/`.

   ## Последствия
   * Положительные: четкая модульность, легкое подключение CI/CD, прозрачность архитектуры для новых участников.
   * Отрицательные: требуется обновить пути импортов в скриптах запуска.
   ```
2. Закоммить созданные изменения:
   ```bash
   git add .
   git commit -m "chore(arch): enforce root hygiene and add ADR-0001"
   git push origin feat/user-dashboard
   ```

## 🏁 Критерий успешности
- [ ] Ты умеешь прятать незавершенный код через `git stash` и восстанавливать через `git stash pop`.
- [ ] Ты выполнил `git fetch --prune`.
- [ ] В корне твоего репозитория нет разрозненных скриптов — код живет в `src/`.
- [ ] В папке `docs/adr/` лежит первый документ `0001-init-structure.md`.
