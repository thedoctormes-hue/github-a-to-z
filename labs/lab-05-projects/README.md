# 🧪 Лабораторная работа №5: Разворачиваем проектный штаб

> **Цель работы:** Настроить доску GitHub Projects, завести задачу (Issue), связать ее с решением через Pull Request, проверить автоматическое закрытие по фразе `Closes #...` и создать свод правил `CONTRIBUTING.md`.

---

## 📋 Пошаговый сценарий

### Шаг 1. Создание первой Канбан-доски (GitHub Projects)
1. На странице своего репозитория (или профиля) на GitHub перейди во вкладку **Projects**.
2. Нажми зеленую кнопку **New project**.
3. Выбери шаблон **Board** (Канбан-доска) и нажми **Create**.
4. Ты увидишь стандартные колонки: `Todo`, `In Progress`, `Done`.

---

### Шаг 2. Создание задачи (Issue)
1. Перейди во вкладку **Issues** своего репозитория.
2. Нажми **New issue**.
3. Заполни карточку:
   * **Title:** `docs: добавить правила для контрибьюторов в CONTRIBUTING.md`
   * **Description:**  
     ```markdown
     ### Что нужно сделать:
     - [ ] Создать файл CONTRIBUTING.md в корне проекта.
     - [ ] Описать правила создания веток.
     - [ ] Описать требования к описанию Pull Request.
     ```
   * В правой колонке:
     * **Labels:** добавь метку `documentation` и `enhancement`.
     * **Projects:** привяжи созданный проект (карточка появится в колонке `Todo`).
4. Нажми **Submit new issue**. Запомни номер задачи (например, `#1`).

---

### Шаг 3. Переход в разработку (Связка ветки)
1. На странице созданного Issue в правой колонке в блоке **Development** нажми **«Create a branch»**.
2. Оставь предложенное имя ветки (например, `1-docs-add-rules`) и нажми **Create branch**.
3. Перейди на свой компьютер в терминал и забери эту ветку:
   ```bash
   git fetch origin
   git switch 1-docs-add-rules
   ```

---

### Шаг 4. Создание файла `CONTRIBUTING.md`
Создай файл `CONTRIBUTING.md` в корне репозитория:
```markdown
# 🤝 Правила участия в разработке проекта

Спасибо, что решили помочь проекту! Пожалуйста, следуйте простым правилам:

1. **Ветки:** создавайте ветки от `main` с понятными префиксами:
   - `feat/...` — новые функции
   - `fix/...` — исправление багов
   - `docs/...` — правки документации

2. **Pull Requests:**
   - Всегда связывайте PR с решаемой задачей через `Closes #номер`.
   - Проверяйте, что код не содержит лишних файлов (проверяйте git diff).

3. **Общение:** будьте вежливы и уважайте чужой труд.
```

Закоммить и отправь ветку на GitHub:
```bash
git add CONTRIBUTING.md
git commit -m "docs: добавлен файл CONTRIBUTING.md с правилами проекта"
git push -u origin 1-docs-add-rules
```

---

### Шаг 5. Открытие PR со связкой `Closes #...`
1. Зайди на страницу репозитория на GitHub и нажми **Compare & pull request**.
2. В описании PR обязательно укажи строку связки:
   ```markdown
   ### Что сделано:
   Создан базовый файл правил для контрибьюторов.

   Closes #1
   ```
   *(Замени `#1` на реальный номер твоего Issue)*.
3. Нажми **Create pull request**.

---

### Шаг 6. Триумф автоматизации (Merge)
1. Открой свой PR и нажми зеленую кнопку **Merge pull request** ➔ **Confirm merge**.
2. Вернись во вкладку **Issues**: твой Issue `#1` **автоматически закрылся** с фиолетовой плашкой `Closed`!
3. Загляни на доску **Projects**: карточка задачи сама перелетела в колонку **Done**!

---

## ✅ Критерии успешного выполнения
1. В репозитории создана Канбан-доска в GitHub Projects.
2. В репозиторий добавлен файл `CONTRIBUTING.md`.
3. Создан Issue с лейблом `documentation`.
4. Issue был автоматически закрыт слиянием Pull Request с ключевым словом `Closes #...`.
5. Карточка на доске перешла в статус `Done`.
