# 🧪 Лабораторная работа №3: Учебное ДТП (Моделируем и разрешаем конфликт)

> **Цель работы:** Специально создать искусственный конфликт слияния веток на локальном компьютере, препарировать маркеры `<<<<<<< HEAD` и научиться спокойно разрешать противоречия в коде.

---

## 📋 Пошаговый сценарий

### Шаг 1. Подготовка полигона
Перейди в свой учебный репозиторий на компьютере (например, `test-git-lab`) или создай временную папку:
```bash
cd test-git-lab
# Убедись, что ты находишься в ветке main и рабочая папка чистая:
git switch main
git pull
```

---

### Шаг 2. Создаем исходную точку
Создай файл `story.txt` с одной строкой текста:
```bash
echo "День 1: На улице светило яркое солнце." > story.txt
git add story.txt
git commit -m "docs: создано начало истории"
git push origin main
```

---

### Шаг 3. Первое изменение (Ветка А)
Представь, что первый разработчик (или ИИ-агент А) решил изменить погоду:
```bash
# 1. Создаем ветку и переключаемся в нее
git switch -c feature-sun

# 2. Меняем текст в файле
echo "День 1: На улице стояла невыносимая жара +35 градусов." > story.txt

# 3. Фиксируем изменение
git add story.txt
git commit -m "feat: уточнена погода (жара)"
```

---

### Шаг 4. Второе изменение (Ветка Б)
А в это же время второй разработчик (или ИИ-агент Б), не зная о первом, начал работу от `main`:
```bash
# 1. Возвращаемся в main
git switch main

# 2. Создаем вторую независимую ветку
git switch -c feature-rain

# 3. Меняем ТУ ЖЕ САМУЮ строку на другой текст
echo "День 1: На улице шел проливной холодный дождь." > story.txt

# 4. Фиксируем изменение
git add story.txt
git commit -m "feat: уточнена погода (дождь)"
```

---

### Шаг 5. Слияние первой ветки (Всё спокойно)
Возвращаемся в `main` и вливаем первую ветку:
```bash
git switch main
git merge feature-sun
```
*Результат:* Слияние прошло гладко (Fast-forward). Теперь в `main` написано про жару.

---

### Шаг 6. Моделируем аварию (Слияние второй ветки) 💥
Теперь пытаемся влить вторую ветку, которая ничего не знает про изменения первой:
```bash
git merge feature-rain
```

**Ты увидишь сообщение:**
```text
Auto-merging story.txt
CONFLICT (content): Merge conflict in story.txt
Automatic merge failed; fix conflicts and then commit the result.
```
Поздравляем! Ты вызвал свой первый настоящий Merge Conflict! 🎉

---

### Шаг 7. Разрешение конфликта
1. Открой файл `story.txt` в редакторе (VS Code или Блокнот).
2. Ты увидишь маркеры:
   ```text
   <<<<<<< HEAD
   День 1: На улице стояла невыносимая жара +35 градусов.
   =======
   День 1: На улице шел проливной холодный дождь.
   >>>>>>> feature-rain
   ```
3. Удали все служебные строки (`<<<<<<<`, `=======`, `>>>>>>>`) и составь компромиссную строчку руками:
   ```text
   День 1: Сначала стояла жара, но к вечеру пошел проливной дождь.
   ```
4. Сохрани файл.

---

### Шаг 8. Фиксация победы
Сообщи Git, что спор разрешен:
```bash
# 1. Проверь статус: Git покажет файл в статусе 'both modified'
git status

# 2. Добавь файл в индекс
git add story.txt

# 3. Заверши слияние коммитом (Git сам подставит пояснение)
git commit -m "fix: разрешен конфликт между погодой в feature-sun и feature-rain"

# 4. Отправь результат в облако
git push origin main
```

Посмотри красивый граф истории в терминале:
```bash
git log --oneline --graph
```
Ты увидишь, как две ветки разошлись в стороны, а затем аккуратно соединились в один узел.

---

## ✅ Критерии успешного выполнения
1. На компьютере смоделирован и успешно разрешен конфликт между двумя ветками.
2. В файле `story.txt` отсутствуют маркеры `<<<<<<<`, `=======` и `>>>>>>>`.
3. В истории коммитов (`git log --oneline`) есть финальный merge-коммит с разрешением конфликта.
4. Изменения успешно отправлены на GitHub.
