## 🎯 Цели полигона

По итогам выполнения этой работы вы:
1. Настроите глобальный `~/.gitignore_global` на вашей рабочей машине и убедитесь, что `.DS_Store` и папки IDE больше никогда не попадут в репозитории.
2. Включите в репозитории опцию **«Automatically delete head branches»** для уничтожения веточных кладбищ.
3. Оформите профессиональный `CHANGELOG.md` по канону **Keep a Changelog**.
4. Отработаете закон неразрывного PR: добавите новую функцию и одновременно обновите документацию и журнал изменений в одном атомарном коммите.
5. Напишете локальный скрипт `pre-commit` хука, блокирующий небрежные коммиты на вашем компьютере.

## 🛠️ Шаг 1: Настройка глобального `~/.gitignore_global`

Защитим все репозитории на вашем компьютере от мусора ОС (`.DS_Store`, `Thumbs.db`, `.vscode/`, `.idea/`).

### 1. Создаем файл в домашней директории:
В терминале:

```bash
# Переходим в домашнюю директорию и создаем файл
touch ~/.gitignore_global
```

### 2. Заполняем его базовыми правилами исключений:
Откройте файл в любом редакторе (`nano ~/.gitignore_global` или `code ~/.gitignore_global`) и вставьте:

```gitignore
# Операционные системы
.DS_Store
.AppleDouble
Thumbs.db
desktop.ini

# Персональные IDE и редакторы
.idea/
.vscode/
*.swp
*.swo

# Временные логи и дампы
*.log
.venv/
__pycache__/
*.pyc
```

### 3. Регистрируем файл в глобальной конфигурации Git:
```bash
git config --global core.excludesfile ~/.gitignore_global
```

### 4. Проверяем санитарный кордон в действии:
Внутри любого Git-репозитория выполните проверку:
```bash
# Создаем фиктивный мусорный файл macOS
touch .DS_Store

# Проверяем статус Git
git status
```
> **Результат:** `git status` **не видит** файл `.DS_Store`! Он полностью невидим для Git и никогда случайно не попадет в коммит.  
> Удалите тестовый файл: `rm .DS_Store`.

## 🛠️ Шаг 2: Включение автоочистки веток на GitHub

Ликвидируем риск превратить репозиторий в кладбище заброшенных веток.

1. Откройте ваш репозиторий в браузере на GitHub.
2. Перейдите во вкладку **Settings** ➔ раздел **General**.
3. Прокрутите страницу вниз до блока **Pull Requests**.
4. Установите галочку напротив пункта **«Automatically delete head branches»**:

```
[✔] Automatically delete head branches
    Deleted branches will still be visible in pull requests.
```

Теперь при каждом слиянии PR GitHub автоматически удалит смерженную ветку на сервере.

## 🛠️ Шаг 3: Создание боевого `CHANGELOG.md` (Keep a Changelog)

Пользователям проекта нужна понятная история изменений, а не сырой `git log`.

Создайте в корне вашего проекта файл `CHANGELOG.md` следующего содержания:

```markdown
# Changelog

Все важные изменения проекта документируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
и проект следует принципам [Семантического версионирования](https://semver.org/lang/ru/).

## [Unreleased]

### Added
- Начата реализация модуля утилит форматирования строк.

## [1.0.0] - 2026-10-12

### Added
- Базовая структура проекта и документация в README.md.
- Настройка файла `.gitattributes` для нормализации строк LF.
```

Зафиксируйте создание файла:
```bash
git add CHANGELOG.md
git commit -m "docs: initialize CHANGELOG.md following Keep a Changelog standard"
```

## 🛠️ Шаг 4: Закон неразрывного PR («Пишем то, что делаем»)

Смоделируем правило: **«Изменил код — обнови документацию в том же коммите»**.

### 1. Создаем рабочую ветку:
```bash
git switch -c feat/slugify-utility
```

### 2. Пишем функцию (код):
Создайте файл `src/utils.py` (или `src/utils.js`):

```python
# src/utils.py
import re

def slugify(text: str) -> str:
    """Преобразует строку в безопасный URL-слаг (lowercase, дефисы)."""
    text = text.lower().strip()
    text = re.sub(r'[^\w\s-]', '', text)
    return re.sub(r'[\s_-]+', '-', text)
```

### 3. НЕРАЗРЫВНЫЙ ШАГ: Одновременно обновляем документацию:
* Откройте `README.md` и добавьте в секцию описания утилит:
  ```markdown
  ### Утилиты (src/utils.py)
  * `slugify(text)` — преобразует произвольную строку в URL-безопасный слаг в нижнем регистре.
  ```
* Откройте `CHANGELOG.md` и добавьте строку в секцию `[Unreleased]` ➔ `### Added`:
  ```markdown
  ### Added
  - Утилита `slugify` для генерации URL-безопасных слагов из строк (`src/utils.py`).
  ```

### 4. Создаем единый атомарный коммит:
```bash
git add src/utils.py README.md CHANGELOG.md
git commit -m "feat(utils): add slugify helper with docs and changelog entry"
```

> **Обратите внимание:** Код, документация и журнал изменений обновлены **в одном атомарном коммите**. Код и дока находятся в 100% синхронности истины!

## 🛠️ Шаг 5: Создание локального санитарного кордона (`pre-commit`)

Создадим простой локальный скрипт Git Hook, который не позволит закоммитить код, если в нем случайно забыли маркер секретов или отладки.

### 1. Создаем скрипт хука:
Хуки Git хранятся в скрытом каталоге `.git/hooks/`. Создадим файл `pre-commit`:

```bash
touch .git/hooks/pre-commit
chmod +x .git/hooks/pre-commit
```

### 2. Наполняем его логикой проверки:
Откройте `.git/hooks/pre-commit` в редакторе:

```bash
#!/usr/bin/env bash
# Санитарный хук: блокирует коммит при наличии критических маркеров

echo "🔍 Проверка санитарного кордона (pre-commit)..."

# Проверяем staged-файлы на опасный маркер TODO(secret) или console.log
if git diff --cached | grep -E "TODO\(secret\)|API_KEY_TEMP"; then
    echo "❌ ОШИБКА: Обнаружен временный секрет или опасный маркер!"
    echo "Коммит заблокирован санитарным кордоном."
    exit 1
fi

echo "✅ Санитарный кордон пройден успешно."
exit 0
```

### 3. Тестируем защиту:
Добавьте в любой файл строку `API_KEY_TEMP = "12345"`:
```bash
echo 'API_KEY_TEMP = "12345"' >> src/utils.py
git add src/utils.py
git commit -m "test: commit with temp secret"
```

> **Результат в консоли:**
> ```text
> 🔍 Проверка санитарного кордона (pre-commit)...
> ❌ ОШИБКА: Обнаружен временный секрет или опасный маркер!
> Коммит заблокирован санитарным кордоном.
> ```
> Git отказался делать коммит! Ваш локальный санитарный барьер спас репозиторий от утечки.

Откатите тестовое изменение:
```bash
git restore src/utils.py
```

## 🏆 Критерии готовности (Definition of Done)

* [ ] В настройках GitHub репозитория включено свойство «Automatically delete head branches».
* [ ] В корне репозитория присутствует оформленный файл `CHANGELOG.md` по стандарту Keep a Changelog.
* [ ] Изменения кода и документации зафиксированы в неразрывном коммите.
* [ ] Проверен локальный pre-commit хук.
