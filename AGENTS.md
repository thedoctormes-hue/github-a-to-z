## 📐 2. АРХИТЕКТУРНЫЕ СТАНДАРТЫ ДЛЯ АГЕНТОВ-РАЗРАБОТЧИКОВ

Если ты выступаешь в роли **Builder Agent** или выполняешь задачу по модификации репозитория:

### 1. Язык и стиль контента
* **Язык:** Грамотный, живой, профессиональный русский язык.
* **Тон:** Доброжелательный, практичный, без академического снобизма и без водянистых рассуждений («AI Slop»).
* **Форматирование:** GitHub Flavored Markdown, таблицы со смайликами статусов, цветные бейджи Shields.io, Mermaid-диаграммы.

### 2. Целостность графа ссылок (Zero Broken Links)
* Каждая относительная ссылка на файл или анкор (`#heading`) должна быть 100% валидной.
* Перед сдачей изменений **всегда запускай валидатор**:
  ```bash
  python3 scripts/validate_links.py
  ```
* Любая сломанная ссылка блокирует сборку в CI!

### 3. Закон неразрывного PR (Atomic Docs & Code)
* Любое изменение в главах или скриптах обязано неразрывно сопровождаться:
  1. Обновлением [`CHANGELOG.md`](CHANGELOG.md) в блоке `[Unreleased]` по стандарту Keep a Changelog.
  2. Обновлением [`README.md`](README.md), если изменилась навигация или перечень файлов.

### 4. Git-гигиена и Conventional Commits
* Все ветки создаются строго с семантическими префиксами: `feat/*`, `fix/*`, `docs/*`.
* Коммиты оформляются по стандарту:
  * `feat: ...` — новый функционал или модуль.
  * `fix: ...` — исправление ошибки или битой ссылки.
  * `docs: ...` — правка документации или опечаток.
  * `chore: ...` — обновление конфигураций, скриптов, CI.

### 5. Безопасность и OPSEC (Zero Leaks)
* Категорический запрет на коммит реальных секретов, паролей, токенов.
* В примерах разрешены только моковые значения (`ghp_mockToken1234567890abcdef`, `ed25519-dummy`).

### 6. Правило для дипломных PR выпускников
* Любой PR в рамках добавления в Зал славы (`graduate/*`):
  * Имеет право изменять **исключительно** файл `GRADUATES.md`.
  * Добавляет ровно 1 новую строчку в конец таблицы.
  * Валидируется автоматическим скриптом `python3 scripts/verify_graduate_pr.py`.
